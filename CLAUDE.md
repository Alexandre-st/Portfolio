# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal portfolio (v2) being rebuilt from scratch with **TanStack Start** (SSR React framework on Vite). The `portfolio-v2` branch holds the in-progress rewrite; `master` is the older version. The `index` route is currently a placeholder — most of the actual portfolio UI is not yet built.

## Commands

Package manager is **yarn** (see `yarn.lock`).

- `yarn` — install dependencies
- `yarn dev` — start the dev server on port 3000 (`vite dev`)
- `yarn build` — production build (`vite build`)

There are no lint or test scripts configured. Type checking runs implicitly via the build; `tsconfig.json` is `noEmit` with `strict` enabled, so run `yarn tsc --noEmit` for a standalone type check.

Deployment is **static (SSG)**: `yarn build` prerenders routes to HTML in `dist/client` (via `tanstackStart({ prerender })` in `vite.config.ts`); Netlify publishes that folder, Cloudflare fronts DNS/CDN. See `docs/IMPLEMENTATION_PLAN.md` for the deploy checklist and `AGENTS.md` for working conventions.

## Architecture

- **Routing** is file-based via TanStack Router. Routes live in `src/routes/`; `src/routeTree.gen.ts` is **auto-generated** — never edit it by hand (it is regenerated by the TanStack Start Vite plugin on dev/build).
  - `src/routes/__root.tsx` defines the HTML shell (`<html>/<head>/<body>`), head/meta tags, and error/not-found boundaries. Global CSS is injected here via `import appCss from "~/styles/index.scss?url"`.
  - New pages are `createFileRoute` modules added under `src/routes/`.
- **Router + data layer**: `src/router.tsx` (`getRouter`) wires a TanStack `QueryClient` into the router context and calls `setupRouterSsrQueryIntegration` so React Query works across SSR. Default `staleTime` is 5 min; `defaultPreload: "intent"`.
- **Path alias**: `~/*` maps to `src/*` (defined in `tsconfig.json`, enabled by `vite-tsconfig-paths`). Prefer `~/...` imports over relative paths.
- **Vite plugin order matters**: in `vite.config.ts` the React plugin must come *after* `tanstackStart()`.
- **Component structure**: feature + ui split — `components/ui` (primitives), `components/layout` (chrome), `features/<section>` (page sections), `data/` (content), `lib/` (github/queries/motion/cn). Each folder has an `index.ts` barrel.
- **Data**: GitHub is fetched **client-side** with React Query (`src/lib/queries.ts`); the site stays static. Animation uses `motion` (`motion/react`) with shared presets in `src/lib/motion.ts`; `<MotionConfig reducedMotion="user">` is set in `__root.tsx`.

## Styling

Global SCSS in **one central `src/styles/` folder** — no CSS Modules, nothing co-located with components. `src/styles/index.scss` (imported once in `__root.tsx`) `@use`s every partial, grouped into sections:
- `globals/` — base layer: `_reset`, `_variables` (design tokens as CSS custom properties; **palette is placeholder pending `portfolio.pen`**), `_fonts`, `_typography`, `_common`, and `_mixins` (`media-breakpoint-up/down`, `pxToRem`, `preset`, `wrapper`).
- `layouts/` (header, footer), `routes/` (per-page, e.g. home), `components/` (button, project-card).

Components use plain global class names (BEM-ish); style partials `@use '../globals/mixins' as *;`. To add styles: create a partial in the right section folder and `@use` it in `index.scss`. Fonts are local Montserrat woff2 in `src/fonts/`.

## Design source (`.pen`)

`portfolio.pen` is an encrypted **pen.dev** design file with exported `pen-assets/`. Access `.pen` files **only** through the pencil MCP tools (`mcp__pencil__*`) — never Read or Grep them directly. This file is the design reference the portfolio UI is being built against.
